# 시대 등장

강호에 진입하면 공개된 Supabase 시대 설정을 한 번 읽어 현재 여정에 복사합니다. 시작일은 현재 턴이고, 1년은 기존 달력의 360일입니다. 이후 관리자 편집은 이미 시작한 시대에 영향을 주지 않습니다.

전체 화면에는 시대명, 소개, 기간, 실제 시작·종료일을 표시합니다. 건너뛰기, Esc, 입장 버튼으로 닫고 상단의 ‘시대 다시 보기’로 재생할 수 있습니다. 기본 효과음은 꺼져 있으며 동작 줄이기 설정을 존중합니다. 작은 화면에서는 본문을 스크롤해도 입장 버튼이 남습니다.

공개 설정이 없거나 연결에 실패해도 일반 행동을 계속할 수 있으며 다시 불러올 수 있습니다. 게임 전용 공개 RPC는 보안 호출자 권한과 기존 RLS를 적용하고 초안을 반환하지 않습니다.

현재 범위는 등장 연출과 시대 시간 표시입니다. 과제 점수 집계, 결과 보상, 20년 종료 기록 및 다음 시대 전환은 아직 연결하지 않았습니다.

## 1단계: 유형과 템플릿 추첨 테스트

관리자 편집실의 **00 시대 추첨 테스트**에서 사용할 수 있습니다. 로그인 후 고정 시드로 추첨하거나 새 시드를 생성하고, 1,000회 분포를 확인합니다. 후보는 아직 로컬 테스트 데이터이며 Supabase에 저장하거나 실제 여정에 적용하지 않습니다.

- 유형: 마교의 준동 / 비급의 행방 / 정파의 분열, 각각 가중치 1.
- 유형마다 템플릿 2개, 각각 가중치 1. 전체 랜덤이면 유형은 1/3, 유형 안의 템플릿은 1/2, 최종 템플릿은 1/6 확률입니다.
- 유형을 지정하면 해당 유형 안에서만 추첨합니다. 빈 후보, 중복 식별자, 잘못된 과제·결과 구성과 가중치는 오류로 처리합니다.
- 템플릿에는 20년 기간, 과제 100점, 0~100점의 연속된 결과 구간을 미리 정의했습니다. 추첨은 수치나 보상을 변경하지 않습니다.
- 단일 추첨 재현 기준은 `era-draw-v1` 알고리즘 + 후보 버전 + 시드 + 유형 선택입니다. 시드는 앞뒤 공백을 제거한 1~128자입니다.
- 분포 검사는 첫 번째에 입력 시드를 쓰고 이후 서로 다른 파생 시드를 사용합니다. 하나의 시드를 1,000번 반복하는 검사가 아닙니다. 화면의 각 비율은 전체 1,000회 기준이며 실제 비율에는 표본 오차가 있습니다.
- 최근 5회 이력은 화면 메모리에만 유지합니다. 게임 진행, 관리자 문서, 초안/공개 상태를 변경하지 않습니다.

후보 데이터: `src/game/era-candidates.js`. 후보나 순서를 바꾸면 `ERA_POOL_VERSION`을 올리고, 추첨 알고리즘을 바꾸면 알고리즘 버전을 올립니다. 다음 단계에서 검토한 후보를 실제 데이터 저장소 및 게임 시작 흐름과 연결합니다.
